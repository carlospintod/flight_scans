**The real run stops at drafting** with a clear message: the three service
keys are Carlos-only infra secrets. To finish the chain for real, set in
`.env` (and later Actions secrets):

1. `ANTHROPIC_API_KEY` — console.anthropic.com key (drafting).
2. `TELEGRAM_BOT_TOKEN` + `TELEGRAM_TEST_CHAT_ID` — create a bot with
   @BotFather, create a private test channel, add the bot as admin, put
   the `-100…` channel id in the env var.
3. `RESEND_API_KEY` — free resend.com account. (`from` stays
   `onboarding@resend.dev` until vuelazo.es DNS/SPF/DKIM exist — Resend's
   test sender delivers to the account owner's own address, which is
   exactly M0's audience.)

Then: `python run_deals.py` (interactive approve) — the verified deal in
the queue picks up from 'verified'/'queued' on the next candidate.

## Implementation choices (and why)

- **Discovery endpoint**: `/aviasales/v3/prices_for_dates` with the
  destination param omitted (documented optional) — one call per
  (origin, month), items carry their own destination. Validated live:
  100 quotes/call for VLC. New metered method `anywhere_prices` on the
  existing client; introspection test pins every `*_prices` method to
  METERED (the kiwi lesson).
- **Route classes**: static `routes/route_classes.yaml` (IATA → class),
  default `medium` for unlisted. **Aviasales returns metro codes (ROM,
  MIL, LON…) and Spanish domestic dests** — both are mapped; the first
  real run caught this (everything unlisted landed in `medium` and
  nothing gated).
- **Cold-start gate** (D2 ratified interpretation): cheapest cached quote
  per route vs the same-day cross-sectional MEDIAN of its route class
  (min 4 routes per class); candidate iff ≥25% below AND absolute saving
  ≥ class floor (30/80/150). Per-route percentile gates arrive with M1
  baselines.
- **Mistake-class at verify time, not gate time**: D2's "below 50% of
  trailing P25" needs per-route history that doesn't exist yet; a
  class-wide P25 falsely flags normal ULCC fares (a 38 € VLC→MRS is not
  an error fare). Cold-start form: live price < 50% of Google
  `price_insights.typical_price_range[0]` (route-specific). Mistake-class
  still requires a 2nd independent live family before publishing — with
  only Google live in M0 it is HELD, never published (D2).
- **"Precio normal" honesty**: prefer Google's typical range
  (route-specific, named as source in the draft), else our same-day
  class cross-section median (also named). Nothing invented; drafts with
  a missing field fail loudly before the API call.
- **Ledger specs for the new rails**: `anthropic` monthly 200 (≈€4/mo
  ceiling), `resend` monthly 3000 with margin 100 (= one worst free-tier
  day in reserve), `telegram` rate_only. These providers publish no
  usable quota counters, so the monthly pools are **self-imposed
  budgets**: run_deals seeds a baseline anchor at period_limit once
  (origin='seed'); re-anchoring at a new month is a deliberate manual
  action until M1 automates it. `env_var=None` in the registry on
  purpose — their keys are infra secrets (CLAUDE.md #6), never /ops.
- **Model**: `claude-opus-5` (config: `routes/vuelazo.yaml` drafting).
  Volume is tiny (≤15 drafts/day); quality of the Spanish product surface
  wins over pennies. Official `anthropic` SDK; refusal stop-reason
  handled before content is read.
- **Booking link**: Google Flights query-style deep link (D9 direct, no
  affiliates). The consent wall that hurt scraping doesn't apply to a
  human clicking once. If click-through UX disappoints, the Kayak
  pre-fill format from the tracker is the tested fallback — but that's a
  D9 conversation, not a code default.
- **Console approve** (M0 spec): `[a]probar / [r]echazar (motivo 1-5) /
  [e]ditar y aprobar / [s]altar`; `--auto-approve` for non-interactive
  runs. Rejections write the one-tap reason to `rejections` (the tuning
  signal). The ops queue UI replaces this in M1.
- **Guardrails live in the gate** and are tested: daily cap 15 (counts
  existing deals), per-route cooldown 7d unless a further −10%, dedup
  ±5% price band, run cap (M0: 1). Kills are printed with reasons,
  never silent.
- **Schema**: full MVP-SPEC §2 columns for `deals`/`fare_observations`/
  `rejections`/`send_log`/`suppressions`/`routes_watchlist` now, so M1
  adds no migration. Suppression list checked before every email send
  from day one. `seo_pages`/`members` wait for their milestones.
- **run_deals reuses the batch lease** (`begin_run`) — a deal run and a
  scan can't stampede each other's reservations.

## Known deviations / deferred

- Aviasales cache serves ~2-month horizons well; `sweep_months_ahead: 2`.
  Week-1 audits (cache freshness per route via `found_at`, market=es,
  insights coverage) are an M1 DoD item.
- Monthly self-pool re-anchor (anthropic/resend) is manual until M1.
- Telegram/Resend/Anthropic clients are constructed in run_deals, not
  `make_clients` (that path stays fare-source-only for run_batch/UI).
- `m0_run_summary.json` is a run artifact (gitignored-worthy; harmless).
