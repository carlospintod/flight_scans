# M2 — Membership (2026-08-08)

## Built

**Python (`lib/members_db.py`, `scripts/member_lifecycle.py`):**
- `members` / `member_events` (entitlement audit trail) / `stripe_events`
  (webhook idempotency) / `member_tokens` (login | tg_bind | unsub;
  SHA-256 stored, CAS consume) — schema owned here, mirrored by the web.
- Lifecycle cron (in deals.yml, 3×/day, idempotent): CAS lapse +
  channel removal (ban→unban so rejoin stays possible), refund-removal
  enforcement, T-30/T-7 renewal reminders (event-log dedup, suppression
  check, one-click List-Unsubscribe headers per RFC 8058).
- Member alert fan-out in `run_deals._publish`: per-airport filtering
  (`active_members_for_origin`), suppression before every send,
  List-Unsubscribe on every member mail, `send_log.member_id` recorded.
  Ledger reserve upper bound = deals × (1 + active members).
- Telegram client grew `create_invite_link` (single-use, 24h expiry) and
  `remove_member` (ban+unban) — both metered.

**Web:**
- `POST /api/stripe/checkout` — Checkout Session, `mode: payment` (D5:
  one-time 12-month, no auto-renew anywhere), prices 2900/3900 cents IVA
  incl., `tax_behavior: inclusive` + `automatic_tax` (Stripe Tax from
  first sale), locale es. Payment methods left automatic so Bizum is a
  dashboard toggle, not a deploy.
- `POST /api/stripe/webhook` — signature-verified on the raw body,
  idempotent via `stripe_events` INSERT-OR-IGNORE gate;
  `checkout.session.completed` → create-or-renew (on-time renewal
  extends from current expiry) + welcome email with magic link
  (`/cuenta#token`) and Telegram deep link; `charge.refunded` → status
  refunded, pass ends now (removal enforced by the lifecycle cron).
- Member auth: `vz_member` cookie (`m1.{id}.{exp}.{hmac}`, Web Crypto,
  SESSION_SECRET), fragment-token consume on explicit POST (the /join
  pattern), magic-link request with Turso-backed IP rate limit and no
  account enumeration.
- `/cuenta` — membership status/expiry, airports preference (min 1,
  logged as airports_set), Telegram bind status, renew CTA, email
  status, logout. `/unete` — the two-price checkout with the D5 copy
  (sin renovación automática · Bizum · 14-day guarantee). `/gracias` —
  what-happens-next.
- `GET|POST /api/unsubscribe?token=` — RFC 8058 one-click; idempotent;
  writes `suppressions` + member_events.
- `POST /api/telegram/webhook` — secret-token-gated bind flow:
  `/start <token>` → CAS consume → bind telegram_user_id → single-use
  channel invite. `scripts/setup_telegram_webhook.py` registers it once.

## Implementation choices

- **Members ≠ users.** Separate table, separate cookie, separate token
  table — customers never mix with tracker operators; deleting one
  system can't cascade into the other.
- **Founding-price retention** (D5) is enforced by what the buyer pays:
  /unete always offers both prices; the renewal email nudges on-time
  renewal to keep 29 €. No server-side price-lock logic in v1.
- **Refund flow** is webhook-sets-state, cron-enforces-consequences —
  the webhook stays fast and idempotent, the ledger-metered cron does
  the Telegram calls.
- Web-tier transactional emails (welcome, magic link) go direct via
  Resend REST (1:1, user-triggered); all BULK mail stays on the
  Python/ledger side.
